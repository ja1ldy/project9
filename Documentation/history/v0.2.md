# Project9 v0.2 — Unix foundations

Version 0.2 adds Unix file permission bits, a primary group per user, and
child status and signals for user programs. It keeps the optimized password
checks and plain prompt from the prior release.

## Bring an existing disk forward

For a new installation, run `make qemu` in a fresh extraction. Choose the
root password when prompted.

For a Project9 v0.1 disk, shut down QEMU and put a **copy** of the old writable
`fs.img` in the new source directory before running `make`. If there is no
`fs.img` when you build, `make` creates a fresh v0.2 disk. Run the following on the host.

```sh
make
make migrate-fs
make qemu
```

`make migrate-fs` installs the v0.2 programs in `/bin`, converts inode
metadata, and saves the old disk as `fs.v01.img`. Your password records and
files outside the installed program paths carry over. Keep the previous
kernel to boot the backup. Running the target on a v0.2 disk reports that
no migration is needed and succeeds. For a v0.1 disk, the target stops if
`fs.v01.img` already exists so it cannot overwrite your backup. If the tool reports a pending
journal, boot the old disk with the old kernel, let it finish starting,
then quit QEMU and try again.

Existing accounts use their UID as their primary GID. Private files and
directories migrate with private modes. Public data keeps its old read
and write policy. Existing ELF programs retain execution access for the
classes that can read them. The system namespace becomes root-owned and
`/tmp` gets mode 1777.

Both formats keep 64-byte inodes and the same disk block layout. The new
inode stores the owner, group and mode, and device numbers occupy the
first two address slots of device inodes. The superblock marks the format
so the new kernel can reject an unconverted disk.

## Permissions

Each process runs with a UID, a primary GID, and a creation mask. Forked
children inherit all three, and they survive `exec`. UID 0 administers the
system. The kernel selects exactly one set of mode bits for ordinary
users, in this order.

| Class | Used when |
| --- | --- |
| Owner | The process UID matches the inode UID |
| Group | The UID differs and the process GID matches the inode GID |
| Other | Neither ID matches |

File modes control reading, writing and execution. Directory modes
control listing, changing entries and searching them. Creating or
removing a name requires write and search on the containing directory.
When a directory is sticky, its owner, the entry's owner and root may
remove names. Set-group-ID directories pass their group to new files
and subdirectories. An executable must have an execute bit even when
root runs it. Existing open file descriptors keep the access they
received at open time.

```sh
umask 077
echo private > /tmp/notes
stat /tmp/notes
chmod 640 /tmp/notes
chown :7350 /tmp/notes
```

Root can use `useradd -g 7350 alice` to give a new account a specific
primary group. Omitting `-g` uses the new UID as the GID. Group IDs are
numeric. The kernel has one group per process, with no supplementary
groups or executable setuid/setgid bits. The account database remains
kernel-only regardless of ordinary mode bits.

## Child status and signals

Use `waitpid(pid, &status, options)` and the macros in `wait.h` to tell
which child exited, stopped or resumed. `exitstatus(n)` records an
eight-bit exit code. Existing `exit()` and `wait()` calls continue
to work with their original arguments. `getppid()` reports the parent PID.

`kill` sends TERM to the selected process by default. Use `kill -s STOP PID`
and `kill -s CONT PID` for direct process control, or Ctrl+Z followed by
`fg` for foreground jobs. `send_signal(pid, sig)` is the corresponding
syscall. `kill(pid)` remains the legacy unconditional kill in C.

Handlers can catch INT, QUIT, TERM, CHLD and CONT. STOP and KILL cannot
be overridden. CHLD is queued when a child exits, stops or resumes.
Ordinary signals coalesce when already pending. The kernel services
stops at safe points, so a process can finish an uninterruptible
kernel operation first.
