# Project9 v0.3 — Shell and userland

## Install

For the pager release, follow the [current installation steps](../man.md).

For a new disk, run `make qemu` and set the root password.

To bring your v0.2 data forward, quit QEMU and copy your old `fs.img` into
the newly extracted v0.3 directory. Then run the following on the host.

```sh
make update-fs
make qemu
```

The installer writes a separate image containing the new `/bin` programs
and `/usr/share/man` pages. It keeps the original as `fs.pre-v03.img` and
preserves accounts, passwords and other files on the working disk. The
on-disk format is the same as v0.2. Fresh images have 256 inode slots. The older `make migrate-fs` target is
for v0.1 disks and installs the current programs during conversion.

You can use the bundled boot and data disks for a new installation.
Keep them paired, or use `make qemu` to build and boot the working disks
at the top of the source tree.

## Use the shell

```sh
PATH=/bin:/usr/bin
LABEL="two words"
export LABEL
printenv LABEL
test -d /tmp && echo ready
false || echo fallback
cat /missing-file 2>&1 | cat
man sh
apropos environment
```

Bare command names use `PATH` in order. An empty entry means the current
directory. The default is `/bin`. An assignment by itself changes the shell.
A leading assignment on a command applies to that command's process.
`export` passes variables to child programs. `unset` removes them.

The shell supports single and double quotes, escaped characters, comments,
`$name`, `${name}`, `$?`, `$$`, positional arguments, and a standalone
`"$@"`. Unquoted substitutions split on whitespace. A quoted substitution
can keep spaces in one argument. `&&` and `||` use the preceding exit
status. A pipeline returns the status of its last stage. The usual file
redirections work, along with descriptor copies such as `2>&1`.

Run a script with `sh file args`. To execute it directly, start it with
`#!/bin/sh` and give it execute permission. Use `if`, `elif`, `else` and
`fi` for conditions, and `for`, `while` or `until` with `do` and `done`
for loops. The interactive shell asks for another line while a quoted word
or compound command is incomplete.

The shell handles `jobs`, `fg` and `bg` on the single Project9 console.
Ctrl+Z stops a foreground job. `bg` resumes it in the background and
`fg` brings it back to the terminal.

## Commands and manuals

The new commands are `man`, `apropos`, `env`, `printenv`, `test`,
`[`, `true`, `false`, `printf`, `cut`, `paste` and `hexdump`.
`grep`, `cmp` and `cat` also return useful statuses for scripts.
Use `man topic`, `man 2 execve`, or `apropos keyword` to look up commands
and interfaces inside Project9. The guest pages are concise text files
under `rootfs/usr/share/man` in the source tree.

The shell has no filename globbing, command substitution, functions,
here-documents, history or tab completion in this release. Redirections
use descriptors 0 through 2. Script files must fit within the 70 KiB
filesystem limit. Arguments and exported environment entries share one
4 KiB stack page at startup, with at most 32 entries per vector.

## Validation

Run `v03test` as root on a test disk. It checks quoting, environment
inheritance, PATH search, conditions, loops, scripts, pipeline status,
redirection, and the manual reader. The final line is
`V0.3 TESTS PASSED`. The v0.2 process and permissions tests remain
available as `v02test`. Run the inherited `usertests` in a disposable
directory or on a test disk.
